# Server

- 2026-08-28 — `server-ts` is the only server. It owns `migrations/` (forward-only, checksummed, advisory-locked) and applies them via `src/migrate` before boot; `src/seed` writes the development dataset after. Both idempotent, both run by compose.
- 2026-08-29 — Everything the frontend calls is served. Still absent: `/runtime`, and the planner's `intent`/`context` stages. See `server-ts/SCOPE.md`.
- 2026-08-29 — Runs are dispatched in process by `runs/dispatcher.ts`: claim with `SKIP LOCKED`, hold and renew a lease (migration 035), execute, sweep the abandoned. The `/internal/runs` surface and its external worker are gone.
- 2026-08-28 — Runs `.ts` directly under `--experimental-strip-types`; `erasableSyntaxOnly` forbids enums, namespaces and parameter properties. No build step.
- 2026-08-28 — Wire shape is a contract: cursor envelopes and idempotency fingerprints already held by clients and stored in the database must keep decoding, so `http/cursor.ts` and `http/canonical-json.ts` are not free to change.
- 2026-09-01 — GitHub is an App Berry creates for itself, not a credential it is configured with. The manifest flow (`/api/v1/integrations/github/app/*`) stores the app id, both halves of the OAuth credential, the private key and the webhook secret sealed with `INTEGRATION_ENCRYPTION_KEY`; repository work runs on installation tokens minted per run from that key. `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` remain only as a fallback for a deployment with no App. Tables arrive in migration `040`.
- 2026-09-01 — **Writing a migration file schedules it for the next API restart.** `038` was written alongside a proposed ADR and applied by a routine `docker compose build && up` before the ADR was accepted; it dropped `goals.source`, which the goals mount still selects, and `/api/v1/goals` answered 500 until `039` reverted it. A migration and the code that needs it belong in the same change.
- 2026-09-01 — `server-ts/SCOPE.md` was rewritten against `src/index.ts`. It had claimed `conversations`, `runs`, `approvals` and `plans` answer 404 long after all four were built. Only `/api/v1/workflows`, `/workflow-runs` and `/hooks` are genuinely unserved.
